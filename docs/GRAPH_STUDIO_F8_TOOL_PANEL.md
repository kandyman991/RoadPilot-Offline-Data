# Graph Studio native F8 connectivity panel — integrated diagnostic workflow

Status: Graph Studio UI and shared Python command engine implemented; Linux/Tauri CI and desktop installation require verification on the PR. This **does not** mean complete/offline F8 production discovery or Android JNI parity is established.

## Using the new UI

Open **Tool → Native F8 connectivity**. Select two **already built** immutable regional routing graph versions from the dropdowns; you do not need to rebuild their `.gph` files. Click **Inspect pair** to bind their exact graph/boundary fingerprints, report whether a matching retained directed edge inventory exists and whether GPS proposal catalogs were already generated.

Click **Discover native GPS proposals** (an explicit, opt-in operation). For a matching, retained uncapped GraphReader scan, reuse those side files, validate full source window catalogs and graph SHA fingerprint declarations and emit directed receiver GPS seeds in **both directions**, preserving every alternative even when there is no cross-graph OSM way peer. Repeating with exactly the same graph fingerprints reuses the existing verified-on-input catalog without rescanning. Otherwise, if a matching C++ GraphReader scanner binary and retained buffer polygons are available, it scans the overlap with progress visible in Graph Studio; if no matching native scanner binary exists, it stops with a clear error instead of silently reviving the retired OSM/frontier pipeline. On the development Legion the scanner can be discovered at the existing Valhalla 3.6.3 development directory; an explicit `ROADPILOT_F8_SCANNER` environment variable can select a compatible binary for other systems. **Fresh native overlap scans can be expensive and are never started automatically by opening the app.**

When a GPS proposal catalog exists, choose Graph A→B or Graph B→A, Motorcycle or Car, enter journey endpoints (or copy from the single-graph Route planner), and click **Run Valhalla journey proof**. The deliberately limited sample budget is 1–16. The shared proof engine checks each sampled independent Valhalla A→GPS→B journey with exact graph SHA/package identity, arrival normalization, traced receiver directed GraphId and full-journey metrics. It preserves prior successful and all untested alternatives. The panel reports count validated vs tested vs **unprobed**, best FASTER/SHORTER **of the tested sample only**, and links tested valid handoffs to the map.

**Cancel F8 operation** terminates the isolated subprocess group without deleting prior immutable files. Graph builds and F8 operations cannot run concurrently. User interface status and logs use Tauri structured command/event plumbing (`f8_pair_overview`, `f8_start_workflow`, `f8_workflow_status`, `f8_cancel_workflow`, `graph-studio://f8-log`, `graph-studio://f8-status`). The same command engine can be used by scripts and AI clients: `tools/graph_studio_f8_workspace.py status|discover|probe`, with explicitly constrained input manifests and paths.

## Evidence ownership and remaining limits

All generated artifacts live under `~/RoadPilotGraphStudio/f8-native/<from>__<to>/<graph-and-boundary-fingerprint>/` with separate `pair.json`, native captured evidence (when needed), deterministic `gps-proposals/`, and per-journey `journey-probes/`. This is a **local diagnostic workspace**, not an Android sidecar or R2 release. Graph `.gph` tiles, routing packs, map packages, historical diagnostics and current Android F8 fallback are never modified.

Existing October 14 standalone scan archives have only **summary-declared** graph SHA provenance and `f8GraphEdgeParity=NOT_VERIFIED`. Although the producer checks the native scanner source and all windows, this is **not cryptographic scan-to-archive attestation** and **not Android JNI scanner parity**. Source window matching is not a proof of full geometric overlap. The UI explicitly reports `Android F8 parity = NOT_VERIFIED` and `Runtime publication = BLOCKED`. A validated *journey sample* is not a proven complete graph-to-graph handoff catalog, does not replace a first-time F8 run for arbitrary routes and does not certify globally optimal FASTER or SHORTER travel.

The next milestones are scalable offline frontier proof scheduling, full directed mode/direction validation, actual Android JNI F8 equivalence against identical graph archive fingerprints (Italy/Austria, Austria/Germany, highways, local roads and multi-hop), finished handoff package generation, and Android package ingestion/rollback tests. The old OSM overlap anchor/correlation/matrix architecture stays deleted. Contract: `docs/ARCHITECTURE_CONTRACT.md`, issues #73/#82 and Android #512.

## Repeatable Legion evidence (2026-10-16)

The GUI's exact command engine was exercised without a second Valhalla graph build. Pair `italy-nord-est__austria`, both immutable routing packs `2026.10.13-1`, existing Valhalla 3.6.3 native side scans reused: **334,973** Italy→Austria and **323,372** reverse directed GPS seeds, including **18,410 / 6,809** without exact physical peer. Normal Valhalla `motorcycle` A→B journey `(46.501885,13.592668) → (46.592234,13.846448)` produced **3 validated out of 6 sampled**, **334,967 unprobed**; the proof is visible in `~/RoadPilotGraphStudio/f8-native/italy-nord-est__austria/` once opened on Legion. Both F8 parity and runtime publication gates stayed closed. Python regressions and TypeScript build were run locally; Rust/Tauri compile, CI and desktop app installation must be separately verified.
